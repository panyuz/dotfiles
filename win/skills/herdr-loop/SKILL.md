# Herdr Loop（Windows）

仅在用户明确调用时执行。可附任务书或已有 TODO 路径。
主代理负责设计、拆分、纠偏和验收。长任务执行交给 hc 终端中的快速模型，减少主代理 token 消耗。

## 1. 授权与模型

- 用户明确调用本技能，视为授权在当前任务范围内派发。
- 授权不扩展到无关任务，也不扩展到多层子派发。
- 用户指定模型时，用户优先。
- 本机验证的默认模型是 `magpie/group/deepseek-flash`。不要写 `magpie/auto/deepseek-flash`。
- 模型不可用或启动失败时停止并报告。不静默换模型，不静默换 CLI。
- 必须核实实际模型与思考强度。`--thinking medium` 本次 footer 显示 high。不从参数假定实际生效。
- 需要另用 pi-subagents 时，先读其 skill。不混用 hc 与原生子代理的等待机制。

## 2. 建立 TODO

在项目任务目录建立 `TODO.md`。已有文件则继续使用。
先写目标、写入范围、验收标准和本阶段时限，再列任务。
用一个文件跟踪计划与进度。工作 brief 与子任务报告可以分开，不算第二份进度文件。
无用户时限时，不自行添加“到期即停止目标”的规则。

```markdown
# 任务目标
范围：
验收标准：
阶段时限：
主代理终端：

## TODO
- [ ] 任务｜执行代理/终端｜模型｜产物｜状态或阻塞

## 交接
下一步：
```

## 3. 派发执行

读取 `hc --skill` 与 `herdr-app --skill`。具体参数用当前命令的 `--help` 现取，不假设旧语法。
用 `hc` 启动、通信、等待和回收终端。`herdr-app` 只在用户要看新窗口、标签或分屏时使用。

- 先执行 `hc templates`。当前模板列表为空。没有合适模板时，直接启动交互式 pi。
- 必须加 `--bg`。禁止 `pi -p`、`--print` 等一次性模式。子代理必须可观察、可接管、可继续。
- 任务书、返工书和报告先实际写入，再确认路径可读，最后在 `hc run` 或 `hc send` 中引用。不要先发送尚不存在的文件路径。
- 首任务放启动参数，不要等启动后再发。示例：

```bash
# 先替换目录，并把任务书写好；任务书中写明具体写入范围和验收标准。
task_dir="C:/path/project/tmp/_session/task/nga"
parent_terminal="$HC_TERMINAL_ID"
# 确认 parent_terminal 非空，再启动；不要把孩子自己的地址作为父地址。
hc run --bg --name forum-nga --cwd "$task_dir" pi --name "NGA 调研" --provider magpie --model group/deepseek-flash "@$task_dir/brief.md" "执行任务书；完成或受阻时向 $parent_terminal 汇报；不派发子代理。"
```

- 模板带任务启动时，核查 `first_message.sent`。直接启动 pi 并带初始提示时，可能没有该字段。缺失不等于 false，也不等于成功。此时读实际首任务和 working / turn 状态确认。只在有具体原因时用 `hc get` 或 `hc read`。
- 父终端地址明确写进子任务指令。子代理不使用自己的 `HC_TERMINAL_ID` 作为汇报目标。
- 命名规则不同，不要要求两端一致：
  - `hc --name` 只接受 1~32 个 `a-z`、`0-9`、`-`、`_`，必须是 ASCII slug。
  - Pi 会话名可用中文或 emoji，用 `pi --name`。
  - 示例：`hc --name bkb-nga` 配 `pi --name 'NGA BKB调研'`，模型参数 `--provider magpie --model group/deepseek-flash`。
- 默认先启动一个后台交互式代理。有独立任务时再增加。
- 每次交付一个清楚子任务。写明输入、允许修改的路径、产物、验收标准和时限。
- 同一目录只设一个写手。并行调研分目录：`tmp/_session/<task>/nga` 与 `tmp/_session/<task>/chh`，各写自己的 `result.md`。主会话独立写正式产物。
- clone 或编辑新仓库前，先查目标是否存在、origin 和 dirty 状态。明确只允许的具体路径。

## 4. 交互约定

子进程主动汇报。主进程有独立工作就继续做。只有需要结果且无独立工作时才等待。

**子进程：**

- 正常执行时继续工作，不逐步发送进度。
- 完成、需要决策或失败时，先保存报告，再执行 `hc send <主进程明确地址> "任务编号｜完成/受阻/失败｜摘要｜报告绝对路径"`。
- 汇报后结束当前轮次，保持交互式代理存活，等待下一条指令。不自行开始下一项任务。

**主进程：**

- 用 `hc send <子终端> "任务编号与任务指令"` 交付后续任务或返工要求。
- 需要等待时，执行 `hc wait --children any --timeout 60`。只有一个指定依赖时，可用 `hc wait <子终端> --timeout 60`。
- 单次等待不超过 60 秒。不 sleep，不轮询截屏。
- `hc get` 与 `hc read` 只用于具体原因：首次就绪、send 未开始、blocked、error、缺报告。
- `hc send` 返回 `started:false` 时先 `hc read`。确有已输入但未提交的消息时，才按当前手册提交既有输入，并核对新轮次。不盲目重发相同任务。
- 不用 `--force` 绕过 blocked 或权限。不在用户显示屏上实验键鼠。

按返回原因处理。不把 wait 返回当作完成：

| 事件 | 主进程动作 |
|---|---|
| 收到子进程汇报 | 按任务编号核对 TODO，读取报告和产物，再验收或处理问题。消息可能在工具返回后到达。 |
| 普通 timeout | 只是 check-in。阶段未到期则继续等待。有独立工作则先做。不重发任务，不重启代理。 |
| `reason=message` | 处理该消息。消息可能稍后到达。 |
| 轮次结束但未收到报告 | 用 `hc get` 核对状态，再用 `hc read` 检查输出。仍无报告且代理可接收指令时，只要求补报。 |
| blocked 或权限请求 | 读取阻塞原因并询问用户。不用强制发送越过权限。 |
| error、异常退出或启动失败 | 保存状态并报告用户。未确认恢复方案前，不重启或替换代理。 |

终端 done 或子进程汇报完成，都不等于产物验收。

## 5. 证据与报告

- 子进程报告要有原帖或原文短引文、URL、日期、板型或版本、读到范围。
- 搜索索引片段不是全文。装机展示不是长期稳定性证据。品牌泛评不是目标型号故障。不能由“没搜到故障”推出零故障或成功率。
- 检查原帖后续是否已解决。只读前半页会把已解决的问题留成“未解决”。报告写当前结论与依据楼层。
- 老站 GB2312 用 Node 内置 `fetch` 加 `TextDecoder('gb18030')` 解码。文本与 API 摘要不一致时看原文。不静默引入依赖。
- PDF 或图片中的表格、示意图与正文冲突时，标明待核实。
- 用户补充机箱、电源、显卡等新信息时，视为更新当前任务，不丢原目标。
- 硬件与 BIOS 类结论按证据分级。官网修复说明不能外推为换板必掉激活。
- 公开原始报告与正式交付分开。主代理抽查高影响结论并纠正。

## 6. 持续推进

循环执行，直到 TODO 全部验收完成：

1. 读取 TODO，将下一项可执行任务交给已登记的代理。
2. 按交互约定处理回报。主代理处理设计与依赖，不接管常规执行。
3. 读取实际产物并运行必要验证。只有验收通过才勾选 TODO。
4. 未通过时，将具体缺口交回原代理。通过后更新证据路径，再派发下一项。

只提供当前子任务所需的上下文。主代理只读摘要、相关产物和验收证据。
子进程汇报完成、轮次结束或 wait 返回，均不能代替产物验收。不静默更换模型。

## 7. 暂停与结束

用户要求状态时，简短答复当前 TODO 摘要，然后继续原任务，除非用户明确要求停下。
只在用户要求暂停，或用户确认的阶段时限到期时暂停执行，并写好交接。
普通 wait timeout 与自行估算的时限，不能结束已授权目标。
恢复时，读取 TODO 并核实已登记终端。仍在工作的代理继续复用。
主代理退出前，暂停执行并保存下一步。只有用户明确要求时，才安排子代理继续运行。
全部验收后，报告产物路径。只 kill 和 rm 本次自建的终端，保留既有用户终端。
长期进度靠文档。不承诺 hc 自动跨重启恢复任务，也不承诺自动继续危险操作。
