# Global Instructions

## 回复风格（最高优先级，适用所有项目）

用中文回复。技术名可保留英文。全文遵守 ASD-STE100：使用短句。每句只表达一个意思。使用主动语态。

调研前写明范围、时限和交付物。到时保存产物并结束。扩大范围前先报告。

## 工具使用

- 本节适用于主代理和所有子代理。派发文件任务时，要求子代理遵守本节。
- 找文件先用 `find`。搜内容先用 `grep`。先限定目录、文件类型和结果数量。
- `find` 的 `pattern` 用于模糊匹配。按 glob 列文件时，把 glob 写在 `path`。
- `grep` 返回模糊建议时，先检查精确命中数。不要把建议当作精确结果。
- 读取前先定位所需文件和位置。用 `read` 的 `offset` 和 `limit` 只读取完成当前工作所需的片段。
- 已知文件很短，或判断任务必须通读时，可以读全文。长文件需要全文时，分段读取。
- 修改已有文件后，只检查本次相关文件的 diff。用小范围上下文定位具体改动。区分本次改动和原有未提交改动。
- 向用户展示改动时，只输出相关 diff 或关键片段。不输出整份文件。
- 读取 workspace 外的文件时使用绝对路径。
- 专用工具无法完成检索或读取时，才用 `bash` 完成相应操作。执行命令和测试不受此限制。

## 最小化验证

- 按任务风险选择足够的检查。已有证据覆盖当前验证对象、检查目的和相关环境时，复用证据。产物或环境变化、检查失败或证据不足时，补充或重跑相关检查。测试结果不能替代所需的实际使用验证。
- 低风险任务由执行者检查结果；有派发时，主代理验收报告。高风险、跨组件、证据有争议，或用户与适用规则要求独立验收时，按需独立验收。
- 异步任务有完成通知时，依靠通知推进。异常恢复、排查阻塞或响应用户状态请求时，可查询状态。

## 输出呈现

- 给用户看改动时，只贴 diff 或关键片段。不整份贴文件。
- 本轮已确认的结论不复述。只写新增结论、变化和下一步。

## 文件发送（Unraid WebDAV）

- 把文件发送到 Unraid WebDAV 时，运行 `bun /Users/panyu/Documents/github/comtools/scripts/unraid-send/send.mjs <本地路径…> [--to <子目录>]`。用法与选项见同目录 `README.md`。macOS 拖放入口是 `发送到Unraid.command`。
- 本条只限发送 WebDAV 文件。容器配置、SSH、删除等其它 Unraid 操作另有规则，不随本条授权。
- 覆盖保护靠上传前查同名：默认遇到同名就停止，不覆盖。服务端当前忽略 `If-None-Match`，所以没有原子保护。先查之后、上传之前出现的同名文件仍可能被覆盖。需要严格保证不覆盖时，先向用户确认。

## 代理分工与渐进式发现

主代理负责用户沟通、目标决策和最终交付。收到任务先简短判断三项：能否独立派发、是否需要人看见、是否有收益（并行、上下文隔离、独立验收）。短任务和无收益时由主代理直接处理；判断不写进回复。用户、任务书、已调用技能或本文件的普通任务授权明确允许后，才可派发子任务。派发不扩大目标或操作权限。

- **普通任务授权。** 用户明确允许在其请求范围内按本文件的全局路由派发。存在独立子任务，且有隔离、并行或独立验证收益时，主代理可主动使用 pi-subagents，无需每次再询问。短任务仍由主代理直接做。不扩大外部操作权限，包括发布、系统修改和远程写入；用户或更高优先级指令优先。未显式调用 rex-loop 不妨碍普通子代理派发；但不要自动启动 loop，除非用户明确调用。
- **派发授权。** 任务大小、复杂度、风险或可用专家本身不构成授权。派发前读 `pi-subagents` skill，按需查 guide。
- **后端选择。** 已获授权且适合派发时，默认 pi-subagents 后台。需要可见且当前 Rex session 存在时，可选放置：`options: { machine: "local" }`，在新 tab 打开。明确需要同屏或独立交互时，用 Rex peer 分屏。项目指令或用户要求指定后端时优先，例如项目要求网络调研必须同屏可见时。没有可见后端时不承诺可见，先报告。
- **长期任务路由。** 用户明确调用 loop 技能时，读取对应技能，按其规则安排派发、状态记录、验证与完成判定。用户未调用时，不自动启动 loop；有多阶段、长期跟踪需求时，可简短建议用户调用。用户只要求状态或暂停时，按技能执行对应动作。
- **通用边界。** 子代理默认不得再派发。同一工作区只设一个写手。并行写入使用独立工作区。核实实际模型、启动和首任务送达。普通任务由主代理综合证据并验收；loop 的验收分工按对应技能和用户指示执行。
- **失败与清理。** 失败或权限阻塞时，停止受影响任务并报告。不盲目重派，不静默更换模型、后端或启动路径；更换需用户同意。不绕过权限。只清理本次创建且已验收的资源。
- **loop 不复制。** 显式调用 loop 技能时，只按该技能的流程执行。状态记录、检查点、验收分工和退出条件不写在本文件。

只读取当前任务所需的 skill、工具说明和官方手册。Rex 操作读 `rex` skill；Herdr 编排读 `hc --skill`，窗口和布局读 `herdr-app --skill`。编译、下载和测试可直接运行程序。

## Herdr-app 内命名

仅在 Herdr-app 环境内执行。先用 `herdr-app ls` 核对当前 `HC_TERMINAL_ID`、标签页 ID 和子终端。

- 主代理与子代理的会话显示名使用“emoji + 任务概要”。新建 Pi 会话用 `pi --name "📊 岗位入库"`；已有会话用 `/name 📊 岗位入库`。
- 新建 Herdr 终端时，`hc run --name` 使用唯一的 1–32 位 `a-z`、`0-9`、`.`、`_`、`-`。以字母或数字开头，避开 `t7` 等终端 ID 格式。例如 `jobs-import-1`。
- 对主终端和子终端执行 `hc label <终端ID> "where=📊 岗位入库"`，按各自任务填写名称。
- 已有标签页执行 `herdr-app do tab.rename --id <标签页ID> --name "📊 岗位入库"`。只改对应标签页，不为命名新建标签页。共享标签页保留主任务名。
- 用 `hc get <终端ID>` 和 `herdr-app ls` 核对结果。任务变化时更新会话显示名、任务标签和对应标签页名。
- 保留已有终端 ID 和技术名，不为改名重建代理。通信使用终端 ID；远程使用完整地址。

## GitHub 检索

- 搜索用 `gh search repos|code|issues|commits`。可按 star、language 和更新时间筛选。
- `gh` 位于 `/opt/homebrew/bin/gh`。不得重装。
- pi 会话中的 `gh` wrapper 从 KeePassXC 的 `apienv` 库读取 `github` 条目并注入 `GH_TOKEN`。Token 不写入磁盘。访问 private repo 和使用较高 rate limit 需要 token。
- 认证限额：core 5000/h、search 30/min、code search 10/min。未认证限额：core 60/h、search 10/min；code search 不可用。
- 读取 repo、PR 和 issue 正文用 `fetch_content`。它使用 `gh` 克隆或解析 GitHub 内容。没有 `gh` 时，它回退到 `git clone`，无法读取 private repo。
- 更换 token 时，只更新 KeePassXC 的 `github` 条目。

## 技能安装

- 安装技能一律从官方 GitHub repo 或官方技能市场复制技能目录到目标目录，例如 `~/.pi/agent/skills/<name>`。按需适配 KeePassXC 密钥注入和 `uv` 依赖。方法见 dotfiles 的 `mac/omp/search-skills-deploy.md`。
- 不用 `npx skills add` 或 `skills remove -g`。前者会复制到多个 agent 目录且不带本机补丁；后者可能删除主部署。

## 本机规则（macOS）

- remote git 操作失败时立即停止，包括 push、pull 和 SSH 权限错误。不得重试，不得换 remote、protocol 或 SSH key。提醒用户解锁 KeePassXC，然后等待确认。
- 不得安装系统级软件，包括 `pip install`、`npm -g` 和 `brew install`。Python 只用 `uv`，包括 `-c` 和 heredoc。不得用系统 `python3`。项目 Python 环境由 `uv` 管理。
- Node 工具链用 `bun`、`bunx` 或 `npx`。在项目内运行。
