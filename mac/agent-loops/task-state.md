# 任务记录示例

已有任务书和记录方式能满足约定时，继续使用。以下字段可按任务裁剪。主代理写任务书和检查点；子代理只写自己的报告。

## 任务书

```markdown
# 任务：<名称>
任务 ID / 目标版本：
用户目标与完成标准：
cwd / 基准版本：
允许写入 / 禁止事项：
当前阶段 / 期限或停止边界：
并发上限 / 模型选择：
独立子任务 / 依赖关系：
产物目录 / 必要验证：
主代理回报地址 / 进度回报时机：
主代理退出后，各子任务继续还是暂停：
```

## 子任务指令

```markdown
任务 ID / 尝试 ID / 目标版本：
目标与必要上下文：
cwd / 基准版本 / 写入边界：
期限 / 验收标准：
产物绝对路径：
回报通道和主代理明确地址：
完成、受阻或到期时回报；不再派发，不扩大范围。
```

只发送子任务所需的上下文。对关键结论给出文件位置或来源。原始报告保留在产物中，避免层层转述。

## checkpoint.md

```markdown
# 检查点
任务 ID / 目标版本 / 更新时间：
总体状态：running / paused / blocked / completed
已验收结果与证据：
未验收报告及路径：
当前计划、依赖与下一步：
剩余时间或阶段边界：
阻塞、失败与用户待决事项：

## 活动资源
| 任务 / 尝试 | 后端 / 机器 | session / tab / block / terminal ID | cwd / 写入归属 | 实际 provider/model | 回报路径 | 最近核实状态 | 本次创建 | 主代理退出后行为 |
|---|---|---|---|---|---|---|---|---|
```

只填当前后端实际使用的 ID。原始 ID 与描述性名称分别保留。资源状态记录观察时间。恢复时重查状态；旧检查点不能证明代理仍在工作。

## 子任务报告

```markdown
任务 ID / 尝试 ID / 目标版本：
状态：已回报 / 受阻 / 失败 / 部分完成
结论和产物绝对路径：
改动文件 / 来源位置：
验证方法、结果与未覆盖项：
阻塞 / 下一步建议：
```

“已回报”只表示生产者提交结果。主代理验收后，再在检查点记录“已验收”。
