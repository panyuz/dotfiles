## 为什么保留一个 main loop

主代理保留用户意图、计划、跨任务判断和最终验收。独立研究、清晰接口的实现和独立验证可使用新上下文。需要反复交换大量细节的步骤保留在同一上下文。

手动调用技能，授权主代理在任务书范围内组织并行工作。用户无需逐轮重复授权。技能本身不授予外部写入、发布、系统修改或再次派发权限。

循环以实际进展推进。它没有固定代理数量或固定轮数。每阶段受目标、期限、预算和验收标准约束。没有可执行下一步时保存状态并暂停。

## 两个后端的差异

| 问题 | Rex | Herdr |
|---|---|---|
| 独立任务放置 | 默认同一 Rex session 内的独立 tab；复用已登记代理 | hc 的后台持久终端 |
| 官方能力发现 | rex skill 与当前 CLI help | hc --skill；需要界面时读 herdr-app --skill |
| 完成通知 | 优先现成通道；本机可选文件回执 | hc 的状态、消息和轮次等待 |
| 等待陷阱 | rex wait 等进程或资源结束，不等模型一轮完成 | 超时、消息、轮次完成和退出含义不同 |
| 界面影响 | 保持用户焦点 | 用户要求时才展示或改变布局 |
| 主代理退出 | 按实际 Rex 能力及任务书约定保留资源 | 父子终端默认有关联，需明确生命周期 |

本机核对了 rex wait --help 和 hc wait --help。Rex 的交互式代理完成任务后可继续存活。若直接等待进程退出，主循环会漏掉已完成结果。因此只为 Rex 补了一个只读文件事件等待器。它不承担模型循环、终端控制或最终验收。

远程文件不自动出现在本机。远程任务必须先建立已验证的消息或产物通道。缺少通道时，技能停在准备阶段。

## 怎样限制失控和信息损失

- 子任务领取完整但紧凑的指令，并返回原始产物路径。主代理核对原始证据。
- 主代理唯一写全局任务状态。每次尝试使用独立 ID，避免迟到回报覆盖当前计划。
- 单写手规则包含主代理。并行写入使用独立工作区。
- 回报不等于验收。任务标准全部通过后才能结束。
- 重连先核对原代理和产物，避免重复执行有副作用的任务。
- 技能不会成为守护进程。退出后的继续依赖真实运行环境或再次手动调用。

## 验证边界

部署验证使用 Pi 当前版本的技能加载器。应能发现两个入口，且自动提示中不出现它们。共享引用应解析到同一份原文。

回执等待器验证现有回执、原子发布、多个候选、普通超时、损坏回执和缺失目录。模拟覆盖完成、阻塞、取消、恢复和旧回报，但不把文档审查当作真实模型回归。

没有实际启动 Rex 或 hc 代理前，只能声称技能结构、加载行为和本机等待器通过验证。不能声称长任务已稳定运行或能自动唤醒主代理。
