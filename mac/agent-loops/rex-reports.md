# Rex 本机文件回执

本机 Rex 子任务使用文件回执，作为主动通知的补收和恢复依据。子代理主动发布回执；主代理运行等待器时由文件事件唤醒。文件回执不提供原生 supervisor 或远程同步，也不会自行唤醒未等待的主代理。

## 建立通道

主代理在项目任务目录中，为每次尝试分配独立的报告路径和回执路径。先创建回执的父目录。把两个绝对路径、任务 ID 和尝试 ID 写进子任务指令。重试使用新的尝试 ID 和新的回执路径。

子代理先完成报告，再向临时文件写回执，最后重命名到指定回执路径。回执格式：

```json
{
  "taskId": "T02",
  "attemptId": "A1",
  "status": "reported",
  "reportPath": "/absolute/project/task-dir/reports/T02-A1.md"
}
```

`status` 只能是 `reported`、`blocked` 或 `failed`。受阻或失败也应写报告，保留部分结果和原因。回执只表示需要主代理处理，不表示验收通过。回执必须是小于 64 KiB 的普通文件。

## 等待一份或多份回执

用当前加载的 rex-loop 技能目录解析脚本路径。通过 Bun 运行，不安装依赖：

```text
bun <rex-loop技能目录>/scripts/wait-report.mjs --timeout-ms 30000 <回执绝对路径> [<其他回执绝对路径> ...]
```

只传当前仍待处理的尝试。脚本先读已有回执，再监听文件系统事件；它处理检查与监听之间的竞态。任一指定回执出现后，脚本输出一行 JSON 并退出。不反复轮询，不启动代理，不操作终端。

| reason | 处理方式 |
|---|---|
| report | 核对任务、尝试和目标版本；读取 reportPath，再验收 |
| timeout | 普通检查点；核对进度和期限，不启动重复任务 |
| invalid-report | 保留文件，检查协议问题，不当作任务成功 |
| watch-error | 检查本机通道和权限，报告阻塞 |

默认等待 30 秒，最长 60 秒。无回执时到期返回。脚本不替代代理状态检查。子代理崩溃或失去文件权限时可能无法回报；主代理应结合检查点，按当前 Rex 手册检查原进程。

回执到达后，从待处理集合移除该尝试。继续等待其余任务时，只传剩余路径。完成任务后仍存活的交互式代理可以继续复用。

## 恢复边界

主代理从检查点恢复时，先核对已接受的尝试及剩余路径。不要把上一次已处理的回执再次当作新结果。目标版本已变的迟到报告保留为历史证据。

远程 session 必须使用已验证的远程消息、文件同步或远程等待能力。不能把远程绝对路径传给本机脚本，并据此声称已建立回报通道。
