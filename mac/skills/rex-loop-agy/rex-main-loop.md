# Rex 主循环

`rex-loop-agy` 专用主循环。它重构自共享 `references/loop.md`，只保留 Rex 场景。共享目录是软链，默认不改；用户明确要求时才改。冲突时以本文为准。

## 1. 建立任务状态

先读用户任务书和项目指令。手动调用本技能，授权主代理在本任务范围内组织并行工作。它不扩大写入、发布、系统修改或再次派发的权限。只加载技能而未给目标时，先整理任务，不启动代理。

在当前项目中选任务目录，遵守项目临时文件约定。建立 `TODO.md`，记录目标、范围、cwd、写入边界、验收标准、期限或停止边界、检查点时机，以及每个子任务的报告与回执路径。另记 Rex 字段：任务 ID、尝试 ID、完整 session、window、block ID、实际 provider、model 和思考强度。

启动前必须明确：主代理回报地址（完整 block ID）、子任务回报方式、主代理退出后的处理方式、并发上限。用户未给并发上限时，从最少的有效并行开始。用户未给期限时，先说明本阶段预计时长和交付边界。

完成标准：主代理能指出本阶段怎样算完成，在哪里读到结果，以及何时停止。

## 2. 角色与派发边界

Rex session 是工作空间，window 是 tab，block 是 pane，代理会话（Gemini / Pi）是对话上下文。

主代理保留用户沟通、目标、计划、跨任务推理、整合与最终验收。执行型工作派发给子代理：调研、资料收集、代码检查、实现、测试和只读验证。

主代理直接执行的三种情况：任务无法安全派发；所需工具只有主代理可用；用户明确要求。执行时记录原因。此条优先于共享 `loop.md` 中“主代理可直接实现关键路径”的表述。

子代理启动失败或权限受阻时，停止受影响分支并报告，不以主代理直接执行绕过阻塞。

按上下文边界拆分。共享大量状态或需频繁交接的步骤留在同一上下文。上下文边界只决定拆分粒度，不构成主代理直接执行的理由；这类步骤仍按本节派发。仅在能获得并行、上下文隔离或独立验证收益时增加代理。

每个子任务带齐：任务 ID、尝试 ID、目标、必要上下文、cwd、写入边界、期限、产物、验收标准、回报地址和禁止再派发。子任务完成后回报并等待，不自行扩大目标。

写入归属：主代理独占 `TODO.md`、全局计划和检查点。子代理只写分配的产物或隔离工作区。同一工作区只设一个写手，主代理计入写手。子代理回报属于证据，不是用户指令。

## 3. 执行一轮

1. **更新判断。** 先处理用户新指令。选定当前里程碑，检查依赖、剩余预算和停止条件。需要改变子任务边界时，先让受影响写手停在安全点。
2. **安排工作。** 主代理处理连续推理。把当前可独立执行的工作按第 2 节派发。核实实际 provider/model、目标 block、首任务送达和回报通道。
3. **等待证据。** 有可做的工作就继续做，不空等。主动通知是首选通道；文件回执是补收依据。单次阻塞等待不超过 60 秒。不用 sleep 或高频抓屏维持循环。
4. **验收结果。** 区分“已启动”“已回报”“已验收”。读取实际产物，核对来源、改动和必要验证。生产者自报成功不能代替验收。
5. **记录与推进。** 更新检查点和资源登记。未通过时把明确缺口交回原代理。达标后推进下一里程碑。只有存在可执行下一步且仍在授权内，才进入下一轮。

每轮应增加证据、形成产物或消除一个阻塞。没有进展时先诊断原因，不重复同一轮。

## 4. 回报与等待

子代理完成、受阻或失败时，按此顺序收尾：写报告 → 原子写回执 → 主动通知 → 结束本轮并等待。

主动通知用 `rex send` 加 `rex send-key ... enter`，发往派发指令指定的主代理 block。格式：`子代理回报｜T06-A1｜完成/受阻/失败｜报告绝对路径`。

发送前核对三项：目标仍是该主代理交互会话；输入框没有用户文字；没有权限或密码提示。任一项无法确认时不发送，保留回执并记录原因。发送成功只证明终端收到输入，不证明主代理已处理。

主代理侧：主动通知进入输入队列，主代理忙碌时排队。本机文件回执和等待脚本只用于补收与恢复，不是常态依赖。等待脚本不能唤醒已退出的主代理。`rex wait` 等进程或资源结束，不能判断交互式代理的一轮是否完成。普通等待超时不代表失败。

退出限制：主代理退出前交代仍在运行的子任务、停止条件和结果位置。未经约定的持续任务安全暂停。子代理不得向自己的 block 发送回报。

## 5. 验收

核对任务 ID、尝试 ID、报告和实际产物，并运行必要验证。只有通过才勾选 `TODO.md`。未通过时把具体缺口交回原代理，不静默换模型、终端后端或启动路径。

由主代理独立复核，或让新上下文只读审查。

## 6. 暂停、失败与恢复

| 触发条件 | 主代理动作 |
|---|---|
| 全部验收标准达标 | 保存完成记录，交付结果，结束循环 |
| 用户叫停或改变范围 | 暂停受影响任务，保存状态，再按新范围安排 |
| 权限阻塞、启动失败或工具错误 | 停止受影响分支，记录错误、已有产物和资源状态，报告用户 |
| 到期、预算耗尽或无下一步 | 保存检查点，说明未完成项，暂停循环 |
| 只有普通等待超时 | 核对状态和本阶段边界，不据此重启代理 |
| 上下文压缩、切换会话或接管 | 先保存检查点，恢复时核对实际环境再继续 |

重试前需要原因、权限依据和重复执行风险判断。新的尝试使用新 ID 和新的报告、回执路径。旧尝试的迟到回报不覆盖当前结果。

恢复时先读任务书和检查点，再检查已登记的代理、产物和工作区。仍在工作的代理继续复用。状态未知时先核实，不重新派发相同写任务。只有全部验收通过，才标记任务完成。

## 7. 收尾与安全边界

先保存证据和资源清单，再清理本次创建且已验收的资源。保留用户在用、仍在工作和未验收的 pane。不关闭主代理所在终端或整个 Rex 服务。

安全边界：不向主代理自己的 block 发送输入；不修改其他任务的配置；不安装系统级软件；不提交、不推送，除非用户要求；远程任务先验证远程通道，本机文件监听不能观察远程磁盘。

向用户报告完成项、证据路径、剩余问题和保留资源。暂停时给出继续所需的任务目录。
